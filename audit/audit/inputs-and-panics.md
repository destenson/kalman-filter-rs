## Suspected, not confirmed
- **`n*n` overflow in `new`:** reaching it needs `x0.len() == n ≥ 2³²`, which is too much memory to allocate in a test. Candidates should still use checked arithmetic there.
- **Large-scale accuracy loss** (`P0=1e20`, nearly collinear `H`: the state stays ≈0 when it should be ≈(1,1)): S has a condition number around 1e15 at that scale, so a correct implementation also loses a lot of accuracy. I could not write a tolerance that a correct implementation is sure to meet.
- **Out of scope, not tested:** in `src/validation.rs`, `estimate_condition_number` indexes `matrix[0]` without a check, so it panics on an empty slice, and `regularize_matrix` indexes without checks.

## Spec problems
- **B5 contradicts itself:** it says "a rank-deficient `r` is valid" but "a zero diagonal is not specified", and a diagonal rank-deficient `R` such as `diag(1,0)` has a zero diagonal. It also never requires the check to be independent of scale (AUD-2), even though B10 requires that for S.
- **B7 lets `predict` return `Ok` with a non-finite result.** There is no rule that `Ok` means finite results, and no rule that `predict` leaves the filter unchanged when it fails (AUD-3, AUD-4). Today a silent overflow later turns into `Ok` with a NaN state.
- **B9 doesn't define "singular" numerically.** It should say the check is relative, e.g. a Cholesky pivot ≤ c·ε·‖S‖. Candidates will pick different thresholds, so tests near the boundary have to accept either `SingularMatrix` or a valid PSD posterior, as AUD-5 does.
- **B11 only checks PSD on two fixed models.** There is no general rule that every `Ok` update leaves P PSD, so a candidate could tune for models A and B and still fail AUD-5.
- **B15 lists zero dimensions, wrong lengths, non-finite values and singular S, but not integer overflow of dimension products** (AUD-1). Q3 only mentions guarding division.
