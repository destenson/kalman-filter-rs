Landed in `src/builders/linear.rs` (new: `LinearKalmanFilterBuilder`, `CovarianceInput`, the constant-velocity preset), re-exported from `src/builders/mod.rs` and `src/lib.rs`; `src/filter.rs` gains `LinearKalmanFilter::constant_velocity` (one line, delegates to the preset) and a shared `checked_model_dims`. New tests are `tests/linear_builder_tests.rs` and `tests/linear_constant_velocity_tests.rs`; no frozen file was touched. This copy has no DESIGN_NOTES.md, so the work started from SPEC.md and the code.
Caller supplies F and H; x0 defaults to zero; P0, Q and R are required and each may be a full Vec, `CovarianceInput::diagonal` or a bare scalar meaning variance·I. Every path ends in `LinearKalmanFilter::new`, so dimensions/finiteness/PSD are validated once; a test feeds eight bad models to builder and new and compares the error text. Constant velocity: dims spatial dimensions, F=[I dtI; 0 I], H=[I 0], Q=q·[[dt³/3, dt²/2],[dt²/2, dt]] per axis, R=r·I, x0=0, P0=I.
Easy: every other filter type already had a builder with the `BuilderIncomplete(field)` convention, so the new front end had a home that defers validation to build.
Hard: build must allocate the default zero initial state before new can reject a zero or overflowing dimension, so new's dimension check was lifted into `checked_model_dims` (one rule, two callers) rather than repeated. "Full matrix, diagonal or scalar" needed a new type; a diagonal must be spelled `CovarianceInput::diagonal`, because for n>1 a length-n Vec is ambiguous.
Verified: frozen 32, lib 108, 18 new tests in f32 and f64, build --all-targets and doctests green; 20-step equivalence is bitwise for dyadic cases.
