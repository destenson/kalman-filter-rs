# Maintainer notes: A / observer-hook

New public `Innovation<'a, T> { y: &[T], s: &[T], nis: T }`, public `InnovationObserver<T>` trait (blanket impl for any `FnMut(&Innovation<'_, T>)`), `LinearKalmanFilter::set_innovation_observer(impl InnovationObserver<T> + Send + 'static)` and `clear_innovation_observer()`, all re-exported from `kalman_filters::linear`. Hook sits in `update`: copies S into a registration-time buffer before the Cholesky (the workspace S becomes the factor), later solves S w = y with the existing `cholesky_solve_rows` for NIS = yᵀw, then calls the observer after `commit()` so only successful steps report. No-observer path: two null checks, no allocation, bit-identical estimates. Manual `Clone` (drops the observer) and `Debug` replaced the derives. New `tests/innovation_observer.rs`, 10 tests including a 5000-step simulated target whose mean NIS is 1.9885 against m = 2.
Easy: update already had y and a factored S, and commit already existed, so the hook is a buffer plus one call; the observer is generic, not boxed, so no allocation and no dynamic dispatch.
Hard: S is overwritten by its Cholesky factor in place, so S had to be copied out before factorisation, costing one preallocated m×m buffer and one extra copy per update; the existing `Clone` derive had to be hand-written because a boxed closure is not `Clone`, and the observer must be invoked after `commit` or a failed step would report.
Verified: lib 108, frozen 32, new 10, doc 11, `cargo build --all-targets` green, clippy clean in the changed files. `linear_kf_robustness` random-model PSD failures are pre-existing at HEAD.
